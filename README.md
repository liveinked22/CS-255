# CS-255
System Analysis and Design

# Project Summary

The DriverPass project focused on designing a system for a company that helps students prepare for their DMV driving exams. The client, DriverPass, wanted a web-based system that would allow students to take online practice tests, schedule on-the-road driving lessons, track their progress, and manage lesson packages. In addition to student features, the system needed to support instructors, secretaries, administrators, and IT staff.
For Project One, I created a Business Requirements Document that outlined the client’s goals, system objectives, functional requirements, and nonfunctional requirements. For Project Two, I developed UML diagrams and a system design document that translated those requirements into a structured system design. Together, these documents demonstrate my ability to analyze client needs and design a system that aligns with business goals.

# What I Did Well

One area I believe I did particularly well was translating business requirements into clear system designs. I carefully mapped user needs into use case diagrams, activity diagrams, sequence diagrams, and a class diagram. I also improved my ability to communicate technical concepts in nontechnical language, especially when creating the client presentation.
Another strength was organizing the system with role-based access and clearly separating responsibilities between students, instructors, administrators, and IT staff. This helped ensure the system was both secure and structured.

# What I Would Revise

If I could revise one part of my work, I would improve the activity diagrams by making them even more detailed from the beginning. As I progressed through the project, I realized the importance of including clearer parallel processes, notifications, and decision points. In the future, I would spend more time refining workflow diagrams early on to ensure they fully represent all system interactions before finalizing them.

# Interpreting User Needs and Design Importance

To interpret the user’s needs, I carefully reviewed the client interview and identified both functional and nonfunctional requirements. I focused on what the client was trying to solve: improving DMV test pass rates through better preparation tools. From there, I translated those goals into system features such as online practice exams, lesson scheduling, progress tracking, and secure payment processing.
Considering the user’s needs is critical in system design because the system ultimately exists to solve their problem. If a system does not align with the user’s goals or is difficult to use, it will not be effective, regardless of how technically advanced it may be. Designing with the user in mind ensures that the final product is practical, secure, and aligned with business objectives.

# My Approach to Designing Software

When designing software, I start by clearly identifying the problem and defining system requirements. I then break the system into smaller components and visualize interactions using UML diagrams. This structured approach helps me see how different parts of the system connect before any implementation begins.
In the future, I plan to continue using techniques such as requirement analysis, role-based design, diagram modeling, and step-by-step workflow mapping. I would also incorporate feedback earlier in the design process and iterate more frequently to refine the system structure. This course strengthened my understanding of how proper planning and system modeling directly support successful software development.
